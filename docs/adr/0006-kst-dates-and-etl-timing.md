# ADR-0006: 경기 날짜는 KST로 저장 + ETL 크론 타이밍

- **Date**: 2026-06-30
- **Status**: Accepted
- **Supersedes**: ADR-0002의 타임존 단순화 노트 (Operational Notes)
- **Related**: PR #64, #71, #74, #75 / ROADMAP S1-18, S2-fix

## Context

미국에서 열리는 경기를 한국 사용자가 본다. 미국 야간 경기는 한국에선 **다음 날**
오전·오후에 끝난다. `game_logs.game_date`를 미국 공식일자로 두면 한국 사용자의
"오늘"과 어긋나고, ETL 크론 시각을 잘못 잡으면 그날 경기가 통째로 누락된다.

실제로 두 가지 사고가 있었다:
1. **하루 밀림**: 옛 데이터가 미국 공식일자로 저장돼 진짜 KST보다 하루 뒤로 표시.
2. **피드 지연**: 크론이 KST 정오(03:00 UTC)에 돌아 미국 경기가 진행 중 →
   "완료 경기만" 규칙에 걸려 누락, 피드가 하루 지연.

## Decision

- **`game_date`는 KST 기준**으로 저장한다: `gameDate`(UTC) → `astimezone(KST).date()`.
  한국은 1988년 이후 DST가 없어 고정 +9 오프셋으로 처리(윈도우 tz DB 의존 회피).
  미국 공식일자 D 경기는 거의 전부 KST D+1로 매핑된다.
- **ETL 크론은 KST 16:00(07:00 UTC)** 에 단일 실행. 가장 늦게 끝나는 MLB 서부
  야간 경기(연장 포함 ~05:55 UTC)까지 마친 뒤라 안전하며, MiLB는 더 일찍 끝난다.
  `roster_sync`는 06:00 UTC로 한 시간 앞서(현재 팀 갱신 후 daily가 필터).
- **"끝나는 즉시" 이벤트 트리거는 불가**(MLB 웹훅 없음, Actions는 cron/이벤트만)
  하고, 잦은 폴링은 비공식 API 차단 위험이 있어 단일 일일 실행을 택했다.

## Consequences

**Positive**
- 한국 사용자의 "오늘"과 피드가 일치. KST 당일 오후엔 그날 경기가 채워진다.
- gamePk 단위로 멱등이라 재실행이 안전(누락 백필·날짜 교정 가능).

**Negative**
- KST 15:00 같은 더 이른 시각은 서부 연장 경기를 가끔 놓쳐 다음 날로 밀릴 수 있어
  채택하지 않음(트레이드오프 검토 결과).
- 데이터 정합성 감사는 **gamePk(타임존 무관)** 로 해야 한다 — 날짜로 비교하면
  규칙 혼선에 휘말린다(과거 사고의 교훈).
