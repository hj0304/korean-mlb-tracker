# 03. 시즌 누적 스탯이 옛날 값에 멈춤 — `season_stats` cron 부재

## 증상
- "이정후 기록이 잘못 들어온 것 같다"는 제보.
- 확인해보니 **과거 시즌(2024·2025)은 MLB와 정확히 일치**, **2026 현재 시즌만** 며칠 뒤처짐
  (우리 `.307/53G` vs 실제 `.321/56G`).

## 원인
ETL cron이 `daily_games`(경기 로그)만 매일 돌고, **`season_stats`(시즌 누적)는 어떤 cron에도 없었다.**
- `daily_games`는 `game_logs`만 갱신 → 경기별 기록은 최신.
- 시즌 합계(`season_stats`)는 마지막 **수동 실행** 시점에 그대로 멈춤.
- 즉 데이터를 "잘못 가져온" 게 아니라 **갱신이 안 된** 것.

## 진단
1. 우리 DB값 vs MLB `yearByYear` 직접 비교 → 과거는 일치, 현재 시즌만 stale.
2. cron 워크플로 목록 확인 → `etl-daily-games`만 존재, `season_stats`용 없음.
3. `daily_games` 잡 코드가 `season_stats`를 건드리지 않음을 확인(서로 독립 잡).

## 해결
- 즉시: `season_stats` 잡 1회 수동 실행 → 2026 값이 MLB와 일치.
- 재발 방지: `etl-season-stats.yml` cron 추가(매일 03:00 UTC = KST 12시), `daily-games`와 **독립 워크플로**(한쪽 실패가 다른 쪽을 막지 않게).

## 교훈
- **"데이터가 틀림"의 절반은 "데이터가 안 갱신됨"이다.** 먼저 *과거는 맞는지* 보면 버그 vs staleness가 갈린다.
- ETL 잡이 여러 개면 **각 잡이 무엇을 갱신하는지**를 명확히 하고, 갱신이 필요한 모든 테이블에 스케줄이 걸렸는지 점검.
- 잡 실행 이력을 남기는 `etl_runs` 같은 테이블이 비어 있으면 이런 진단이 느려진다 → 관측성의 가치.
