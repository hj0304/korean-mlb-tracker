# 06. MiLB 데이터 수집의 함정 — yearByYear는 기본이 MLB만

## 증상
MiLB 한국인 선수를 추가했는데:
- 시즌 스탯이 0행으로 나오거나(투수·유망주), 마이너 시절이 통째로 누락.
- 일부 선수는 MLB Stats API **이름 검색(`/people/search`)에서 아예 안 나옴**.

## 원인 / 함정 모음
1. **`stats=yearByYear` 기본값은 MLB(sportId 1)만 반환.** MiLB 시즌을 얻으려면 `sportId`를 명시해야 함. 게다가 **콤마 다중값 미지원** → 레벨(1/11/12/13/14/16)마다 **개별 호출**.
2. **한 선수가 한 시즌에 여러 레벨**에서 뜀(승격/강등). season_stats PK가 `(player_id, season, group)`이라 시즌당 1행만 가능 → 어떤 레벨을 쓸지 선택 필요.
3. **현재 레벨 ≠ 시즌 주력 레벨.** 예: 김혜성은 현재 AAA지만 2026 주력은 MLB.
4. **이름 검색 인덱스에 신규 유망주가 없음** → ID를 못 찾음. 또 로마자 표기가 제각각(심준석=Shim, 장현석=Jang…).
5. 선수 기본 `/people/{id}` 응답엔 **레벨 정보가 없음**(팀 sport를 따로 조회해야 함).

## 진단 / 해결
- **(1)(2)** 레벨별로 `yearByYear`를 호출해 payload들을 모은 뒤, `(시즌, 그룹)`마다 **gamesPlayed가 최대인 split**을 채택. 이 한 규칙이 *같은 레벨 다팀 통합(numTeams)* 과 *레벨 이동 시 주력 레벨 선택* 을 **동시에** 해결. 채택된 레벨은 `stats.level`에 저장.
- **(3)** roster의 `current_level`(현재 소속)과 season의 시즌 레벨은 **의도적으로 다른 의미**로 둠.
- **(4)** 이름 검색 대신 `/sports/{sportId}/players?season=`로 **레벨별 전체 명단을 받아 국적(Republic of Korea)으로 필터** → 신규 유망주까지 ID 확정.
- **(5)** `/people/{id}?hydrate=currentTeam` → `currentTeam.id` → `/teams/{id}`의 `sport.id` → 레벨 매핑(1=MLB,11=AAA,12=AA,13=A+,14=A,16=R).
- 일일 경기도 전 레벨 스케줄을 받되, **우리 팀이 낀 경기만** 박스스코어 조회(하루 수백 경기 → ~14콜).

## 교훈
- 비공식 API는 **기본값이 곧 함정**이다. "왜 비었지?"는 보통 **스코프 파라미터(sportId 등)** 누락.
- 실제 응답을 **fixture로 저장 + snapshot 테스트**해두면 구조 변화·가정 오류를 빨리 잡는다.
- 1:N 관계(한 시즌 여러 레벨)를 단일 PK 테이블에 욱여넣을 땐 **선택 규칙을 하나로 단순화**(여기선 "경기수 최대")하면 코드가 깔끔해진다.
